# Roky 스타일 기술 블로그 작성법

이 문서는 Roky 스타일의 기술 블로그 포스팅을 작성하는 방법을 설명합니다.

## 핵심 특징

### 말투 및 톤
- **한국어 반말**: ~이다, ~했다, ~보자, ~하겠다
- **직접적이고 단도직입적**: 불필요한 수식어 없이 핵심만 전달
- **친근하면서 전문적**: 기술적 깊이를 유지하되 독자와 대화하듯 작성
- **솔직한 학습 과정 공유**: 실패 경험, 시행착오, 고민 과정을 숨기지 않음
- **겸손한 태도**: 더 좋은 방법이 있다면 조언을 구하는 마무리

### 특징적 표현
- "~를 살펴보자" / "~에 대해 알아보자"
- "이번 글에서는 ~에 대해 상세히 설명하겠다"
- "이제 ~를 비교해보자"
- "그래서 나온 것이 ~이다"
- "내가 생각하기엔"

## 글 구조

### 1. 도입부
개인적 경험이나 학습 계기로 시작:
- "~를 공부하면서 ~를 훑어봤지만, 스터디에서 해당 주제가 나왔을 때 제대로 답변하지 못했다"
- 글의 목적을 명확히 제시: "이번 글에서는 ~에 대해 상세히 설명하겠다"

### 2. 본문

#### 원리 설명
- 기본 개념부터 차근차근 설명
- "~를 살펴보자", "~에 대해 알아보자" 같은 표현 사용
- 필요시 다른 개념과의 비교

#### 문제 상황 (해당되는 경우)
- ⚠️ 이모지로 문제 상황 강조
- 구체적인 시나리오나 코드로 문제 재현
- "예를 들어서", "만약 ~한다면" 등으로 예시 제시

#### 해결 방법
- 🛠️ 이모지로 해결책 섹션 구분
- 여러 해결책이 있다면 모두 제시하고 비교
- 각 해결책마다 **완전한 코드 제공** (부분이 아닌 전체 코드)
- 코드에 한국어 주석 포함
- 중요한 차이점은 주석으로 강조 ("★ ~와 차이점 1:")

#### 비교 및 분석
- 여러 방식의 장점/단점을 명확히 구분
- 구체적인 수치와 예시 사용
- 테스트 결과나 벤치마크 제시
- 표, 로그, 스크린샷 등 시각 자료 활용

#### 구현 중 발생한 에러 (해당되는 경우)
- 실제 에러 메시지 전체 포함
- 원인 분석
- 해결 과정을 단계별로 서술

### 3. 검증 및 테스트
- 실제 테스트 결과 제시
- K6 부하 테스트, JVM 프로파일링 등 구체적인 도구 언급
- Redis MONITOR 로그, 데이터베이스 쿼리 로그 등 실행 로그 포함
- 비교 대상이 있다면 표나 그래프로 정리

### 4. 마무리: "마치며"
- 학습한 내용 요약 또는 소감
- 겸손한 태도로 추가 조언 요청
- 예시: "혹시 좀 더 좋은 ~에 대해서 아시는 분이 계시다면 조언해주시면 정말 감사하겠습니다"

## 코드 작성 지침

### 완전성
- 전체 클래스/함수를 완전히 제공 (일부 생략하지 않음)
- 한국어 주석 포함
- 여러 구현 방식이 있다면 모두 제시
- 각 방식마다 "사용예시" 섹션 추가

### 출처 표기
코드 블록 하단에 출처 명시:
```
출처: [URL]
```

### 주석 스타일
```java
// 기본적인 설명
// ★ 중요한 차이점이나 주의사항
```

## 이모지 사용 규칙

- ⚠️: 문제 상황 발생, 주의사항
- 🛠️: 해결 방법, 구현
- ✅: 성공, 허용
- ❌: 실패, 거부
- 📊: 테스트 결과, 벤치마크

## 기술적 깊이

### 원리 중심 설명
- 원리부터 설명
- 구체적인 수치와 예시로 설명
- 장점/단점을 명확히 구분
- 트레이드오프 분석
- 공식 문서나 Wikipedia 등 신뢰할 수 있는 출처 참조

### 실패 경험 공유
- 에러 메시지 전체 포함
- 시행착오 과정을 솔직하게 서술
- "처음에는 ~했지만", "~해봤더니", "알고보니" 같은 표현
- 최종적으로 어떻게 해결했는지 명확히 제시

### 비교와 대조
- 여러 방식을 표로 정리
- "첫 번째 구현 방식", "두 번째 구현 방식" 등으로 구분
- "~와 차이점은"으로 비교 시작
- 장점/단점 섹션을 명확히 구분

## 출력 형식

- Markdown 형식
- 코드 블록은 언어 지정 (```java, ```kotlin, ```bash 등)
- 섹션은 ##, ### 로 구분
- 중요한 부분은 **굵게** 처리
- 리스트는 `-` 또는 번호 사용

## 작성 시 주의사항

### 금지사항
- 존댓말 사용하지 않기 (반말 유지)
- 과도한 수식어나 형용사 자제

### 권장사항
- 실용적이고 구체적인 내용 중심
- 이론만이 아닌 실제 구현과 테스트 결과 포함
- 독자가 따라할 수 있을 정도로 상세하게 작성
