# Anki 카드 생성 포맷

## 기본 구조

```markdown
## [질문 제목]

<details>
<summary>꼬리 질문</summary>
<div>

- 실제 꼬리 질문 1
- 실제 꼬리 질문 2

</div>
</details>

<details>
<summary>답변 보기</summary>
<div>

**메인 질문 답변**

[개념 정의 → 원리 → 예시 → 활용 → 관련 개념 순서로 자연스럽게 연결된 완성된 답변]

- 핵심 포인트 💡:
  - 실제 핵심 개념 설명
  - 구체적인 원리나 동작 방식
  - 실무 활용 사례

- 개념 정의와 원리
  - 구체적인 설명과 함께 출처 명시
  - [출처명](링크)
  - > 위 출처에서 "원문 인용" 이라고 명시되어 있음.

- 실제 동작하는 코드 예시
  ```언어
  // 구체적이고 완성된 코드
  ```

- 활용 방법과 실무 사례
  - ✅ 올바른 사용: 구체적인 예시
  - ❌ 흔한 실수: 구체적인 안티패턴

---

**꼬리 질문 1: [질문 내용 반복]**

💬 면접 답변 (1-2분 분량)

[면접관에게 직접 말로 전달할 완성된 답변. "~입니다", "~했습니다" 등 실제 면접 어투로 작성]

- 출처: [출처명](링크)
- > 위 출처에서 "원문 인용" 이라고 명시되어 있음.

</div>
</details>
```

## 작성 규칙

### 필수 사항
1. **실제 내용 작성**: 플레이스홀더가 아닌 실제 내용
2. **출처 명시**: 각 내용마다 `[출처명](링크)` 형식 + 원문 인용
3. **자연스러운 구성**: "~입니다", "~했습니다" 등 실제 설명 어투
4. **핵심 집중**: 질문에 대한 직접적인 답변만 제공

### 답변 구조
- 개념 정의 → 원리 → 예시 → 활용 → 관련 개념 순서
- 핵심 포인트 💡: 3-4개 요점 정리
- 구현 예시: 실제 동작하는 코드
- 정답/오답: ✅ 올바른 방법, ❌ 흔한 실수
- h tag 사용 금지, li tag depth로 구분

### 금지 사항
- 추측이나 불확실한 정보 제공
- 질문과 무관한 부가 설명
- 검증되지 않은 내용
- div 태그 밑에 markdown이 들어오는 경우 반드시 사이에 공백이 있어야 함
