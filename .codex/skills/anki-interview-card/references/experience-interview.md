# 경험 면접 평가: 선택의 흐름 5단계

## 평가 대상

**프로젝트 경험, 문제 해결, 시스템 설계** 관련 질문:
- "성능을 개선한 경험이 있나요?"
- "가장 어려웠던 기술적 문제는?"
- "팀과 의견 충돌이 있었을 때 어떻게 해결했나요?"

## 선택의 흐름 평가 기준 (각 20점, 총 100점)

### 1장: 문제의 발견 (Problem) - 20점

**핵심 질문:**
- 어떤 문제가 있었나?
- 왜 이게 문제인가? (비즈니스 임팩트)
- 어떻게 발견했나? (측정)

**좋은 답변 예시:**
"상품 조회 API가 P95 기준 800ms로 측정되었습니다. 피크 시간대 timeout 에러 5% 발생, 예상 매출 손실 월 1억원. Datadog APM 알람으로 인지했습니다."

### 2장: 선택지 탐색 (Options) - 20점

**핵심 질문:**
- 어떤 해결 방법들을 고려했나?
- 각 방법의 장단점은?
- 왜 이 3가지로 좁혔나?

**좋은 답변 예시:**
"3가지 해결 방안 검토:
- Option 1: DB 쿼리 최적화 (800ms → 200ms, 비용 없음, 목표 미달)
- Option 2: Redis 캐싱 (800ms → 15ms, 월 30만원, 캐시 정합성 관리)
- Option 3: CDN (10ms, 동적 데이터 부적합, 비용 높음)"

### 3장: 결정의 근거 (Decision) - 20점

**핵심 질문:**
- 왜 이 방법을 최종 선택했나?
- 무엇을 우선순위로 뒀나?
- 팀과 어떻게 합의했나?

**좋은 답변 예시:**
"Redis 선택. 결정 근거: 목표 100ms 달성 유일, 트래픽 80%가 상위 20% 상품에 몰려 캐싱 효율 높음, 팀원 3명이 Redis 경험 보유. 3가지 옵션 문서화하여 팀 리뷰, Fallback 전략 합의."

### 4장: 구현의 여정 (Action) - 20점

**핵심 질문:**
- 어떻게 구현했나? (디테일)
- 어떤 문제를 만났na?
- 그 문제를 어떻게 해결했na?

**좋은 답변 예시:**
"Redis Cluster (Master 3, Replica 3) 구성. Key: `product:{id}:{version}`, TTL: 5분. 문제: Cache Miss 폭증 → Warming 스크립트, 메모리 부족 → allkeys-lru, 장애 대비 → Circuit Breaker"

### 5장: 결과와 학습 (Result) - 20점

**핵심 질문:**
- 어떤 결과를 만들었나? (수치!)
- 무엇을 배웠na?
- 다시 한다면 어떻게 개선하겠na?

**좋은 답변 예시:**
"응답시간 P95: 800ms → 250ms (68% 개선), Timeout 에러 5% → 0%, 캐시 히트율 78%. 매출 증대 월 5천만원. 배운 점: 측정 없는 최적화는 도박. 다시 한다면: A/B 테스트로 점진적 배포"

## 필수 체크리스트

- [ ] **논리적 흐름**: 문제 → 대안 → 결정 → 구현 → 결과 연결
- [ ] **문제 정의**: 구체적인 수치와 비즈니스 임팩트
- [ ] **원인 분석**: 측정 기반 분석
- [ ] **대안 비교**: 여러 선택지 장단점 분석
- [ ] **비즈니스 가치**: 기술 선택과 비즈니스 가치 연결
- [ ] **팀 협업**: 팀과의 소통과 합의 과정
- [ ] **구현 디테일**: 구체적인 기술적 결정과 근거
- [ ] **문제 해결**: 구현 중 만난 문제와 해결 과정
- [ ] **측정 가능한 결과**: 구체적인 수치로 성과 제시
- [ ] **회고와 학습**: 배운 점과 개선점

## 감점 요소

- ❌ "그냥 그런 것 같았다" (측정 없는 추측)
- ❌ "요즘 많이 쓰여서" (비즈니스 가치 부재)
- ❌ "배우고 싶어서" (RDD)
- ❌ 논리적 비약
- ❌ 후속 문제 미고려
- ❌ 모호한 표현
