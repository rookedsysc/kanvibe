## 작성 규칙

### 필수 사항
1. **두 파트 구조**: 💬 면접 답변 + 📋 상세 분석 모두 포함
2. **실제 내용 작성**: 플레이스홀더가 아닌 실제 내용
3. **출처 명시**: 각 내용마다 `[출처명](링크)` 형식 + 원문 인용
4. **핵심 집중**: 질문에 대한 직접적인 답변만 제공

### 💬 면접 답변 작성 규칙
- **2-3분 분량**: 실제 면접에서 말할 수 있는 길이
- **자연스러운 구어체**: "~입니다", "~했습니다" 등
- **흐름있는 구성**: 여러 단락으로 나누어 서론-본론-결론
- **섹션 헤더 없음**: 제목 없이 자연스럽게 연결
- **항목 나열 시**: "첫째, 둘째, 셋째" 등 사용
- **면접관에게 말하는 톤**: 설명하듯이 작성

### 📋 상세 분석 작성 규칙
- **CLEAR 프레임워크 준수**: Concept → Logic → Example → Application → Relation
- **핵심 포인트 💡**: 3-4개 불릿으로 요약
- **각 섹션마다 출처**: 반드시 원문 인용구 포함
- **실제 동작 코드**: 복사해서 실행 가능한 예시
- **비교 테이블**: 관련 개념 비교 시 활용
- **트레이드오프**: 장점/단점 명시
- **h tag 절대 사용 금지** (`###`, `####` 등) - 모든 구조화는 **볼드 텍스트**와 li tag depth(`-`, `  -`)로만 구분

### 금지 사항
- 추측이나 불확실한 정보 제공
- 질문과 무관한 부가 설명
- 검증되지 않은 내용
- div 태그 밑에 markdown이 들어오는 경우 반드시 사이에 공백이 있어야 함
- **h3, h4 등 heading 태그 사용 절대 금지** (예: `### 섹션 제목` ❌)
- 💬 면접 답변에서 불릿 포인트나 섹션 제목 사용

## 올바른 예시 vs 잘못된 예시

### ❌ 잘못된 면접 답변 (불릿 포인트 사용)
```markdown
💬 **면접 답변 (2-3분 분량)**

- Java는 객체지향 언어입니다.  ← 불릿 포인트 사용 금지!
- 다음과 같은 특징이 있습니다:
  - JVM 위에서 동작
  - GC 지원
```

### ✅ 올바른 면접 답변 (자연스러운 단락)
```markdown
💬 **면접 답변 (2-3분 분량)**

Java는 객체지향 프로그래밍 언어로, "Write Once, Run Anywhere"라는 철학 아래 설계된 플랫폼 독립적인 언어입니다. Java의 주요 특징은 크게 다섯 가지로 정리할 수 있습니다.

첫째, 객체지향 언어로서 캡슐화, 상속, 다형성, 추상화를 지원합니다. 둘째, JVM 위에서 동작하여 플랫폼 독립성을 제공합니다. Windows에서 컴파일한 .class 파일을 Linux에서도 그대로 실행할 수 있습니다. 셋째, Garbage Collector를 통한 자동 메모리 관리로 개발자가 메모리 해제를 직접 관리할 필요가 없습니다.

결론적으로 Java는 안정성과 생태계가 중요한 대규모 엔터프라이즈 환경에 적합합니다.
```

### ❌ 잘못된 상세 분석 (h tag 사용)
```markdown
📋 **상세 분석 (암기/복습용)**

### Concept - 개념 정의  ← h tag 금지!
Java는...

### Logic - 원리  ← h tag 금지!
동작 방식...
```

### ✅ 올바른 상세 분석 (볼드 + li depth)
```markdown
📋 **상세 분석 (암기/복습용)**

**핵심 포인트 💡**
- Java는 "Write Once, Run Anywhere" 철학의 플랫폼 독립적 객체지향 언어
- JVM + GC + 멀티스레딩 + 보안이 핵심 특징

**Concept - 개념 정의**  ← 볼드 텍스트로 제목

Java는 Sun Microsystems가 1995년 발표한 객체지향 프로그래밍 언어로, JVM 위에서 동작하여 플랫폼 독립성을 제공합니다.

- 출처: [Oracle Java 공식 문서](link)
- > 위 출처에서 "Java는 간단하고, 객체지향적이며..." 이라고 명시되어 있음.

**Logic - 원리/동작 방식**

Java의 플랫폼 독립성은 다음과 같이 동작합니다:

1. 개발자가 .java 소스 코드 작성
2. javac 컴파일러가 .class 바이트코드로 변환
3. JVM이 바이트코드를 OS별 기계어로 변환

- 출처: [JVM 동작 원리](link)
- > 위 출처에서 "JIT 컴파일러는..." 이라고 명시되어 있음.
```
