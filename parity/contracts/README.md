# HTTP/WebSocket contract goldens

These files record how the TS (Electron) server answered the clients that must keep working against the Rust server without changes: the Flutter mobile app, the installed agent hooks, and the task CLI. A replayer sends each recorded request to a server and compares the response with the golden.

The goldens are frozen data. The TS app and the recorder (`record.py`, `scenario.py`, `coverage.py`) were removed with the rest of the TypeScript code; they remain in git history up to commit `a73f3498`. Do not hand-edit the goldens.

| Path | Content |
|---|---|
| `cases/NNN_<id>.json` | One golden case per file. `NNN` is the replay order. |
| `manifest.json` | Format version and the ordered list of case files. A replayer must use this order. |
| `coverage.md` | Inventory route → golden case IDs, plus the routes and behaviors that were not recorded and why. Generated by the removed recorder. |
| `../tools/contracts/replay.py` | Python reference replayer. Works against any server. |

## Commands

```sh
# Replay against a server that is already running
python3 parity/tools/contracts/replay.py --base-url http://127.0.0.1:39736 --oracle-cmd ./rust-contract-oracle

# Build the Rust QA server and replay against a fresh isolated instance of it
cargo build -p kanvibe-server --bin kanvibe-server-qa
python3 parity/tools/contracts/replay.py --launch-rust target/debug/kanvibe-server-qa
```

`--launch-rust` starts `kanvibe-server-qa serve --data-dir <run>/appdata --hook-port <port> --oracle-socket <sock>` with the same narrow child environment the goldens were recorded in (`kvcontract/rustapp.py` uses `kvcontract/child_environment.py`). The server wires the real services (`kanvibe-runtime`, `kanvibe-mobile`, `kanvibe-pane-mirror`) exactly as the app does. Its oracle command is `kanvibe-server-qa oracle --socket <sock> <name> '<json-args>'`; the socket is a 0600 Unix socket opened only by the QA runner, never a network port.

Replay always needs a fresh server with an empty database. Cases build state in order (pair → register projects → create tasks → delete), so a second replay against the same server fails on duplicates.

## Case format

```json
{
  "seq": 72,
  "id": "mobile.tasks.create.ok",
  "group": "tasks",
  "route": "POST /api/mobile/tasks",
  "title": "create a tmux task (worktree + hooks + targets.json)",
  "transport": "http",
  "setup": ["human-readable preconditions beyond the earlier cases"],
  "oracles": [{"name": "read_json_file", "args": {"path": "{{var:task_worktree}}/.kanvibe/targets.json"}, "save": {"task_token": "targets[0].token"}}],
  "delay_before": 1.2,
  "request": {
    "method": "POST",
    "path": "/api/mobile/tasks",
    "listener": "plain",
    "headers": {"Authorization": "Bearer {{var:pair_token}}", "Content-Type": "application/json"},
    "body": {"projectId": "{{var:project_id}}", "branchName": "feat-a", "baseBranch": "main"}
  },
  "capture": {"task_id": "body.task.id", "task_worktree": "body.task.worktreePath"},
  "expect": {
    "status": 200,
    "headers": {"content-type": "application/json", "cache-control": null},
    "body": {"success": true, "task": {"id": "{{any:uuid}}", "worktreePath": "{{var:demo_repo}}__worktrees/feat-a", "createdAt": "{{any:iso8601}}"}}
  }
}
```

Replay steps for one case:

1. Sleep `delay_before` seconds if it is set. `createdAt` has one-second resolution, and ties in ordered lists are not stable. The delay keeps the creation order of listed entities strict.
2. Run each `oracles[]` entry in order, and store the fields named in `save` as variables.
3. Replace every `{{var:x}}` in `request` (and in `steps` for WebSockets) with the variable's value. If the whole string is one reference, the value keeps its JSON type.
4. Send the request, then compare the result with `expect` (see Comparison).
5. Run `capture`, so that later cases can refer to the new variables. Do this even when the comparison failed.

### Request fields (`transport: "http"`)

| Field | Meaning |
|---|---|
| `listener` | `plain` = hook port (HTTP). `tls` = hook port + 10 (HTTPS, self-signed, verification off). |
| `headers` | Sent exactly as given. Auth placeholders: `Bearer {{var:pair_token}}` (device token), `Bearer {{var:task_token}}` (HMAC task token). The client adds only `Host` and `Content-Length`. No `Accept-Encoding` or `User-Agent` is sent. |
| `body` | JSON value, serialized compactly (`separators=(",", ":")`, UTF-8, no ASCII escaping). This matches Dart's `jsonEncode`. |
| `body_text` | Raw body text. Used for invalid JSON. |
| `body_fill` | Generated body of exactly `bytes` bytes: `prefix` + `"a"` repeated + `suffix`. Used to test body limits. |

Use a new TCP/TLS connection for each request.

### Expectation fields (`transport: "http"`)

- `status`: exact HTTP status.
- `headers`: only `content-type` and `cache-control` are compared, case-insensitively by name. `null` means the header must be absent. The TS server sends `application/json` with no charset for JSON, and `text/plain; charset=utf-8` for the hook install script.
- `body`: the parsed JSON when the response `content-type` starts with `application/json`. Otherwise `body_text` holds the raw text.
- `tls.peer_certificate_sha256`: for TLS requests, the certificate the server presented (SHA-256 of the DER, lowercase hex, no colons). It is always `{{var:tls_fingerprint}}`, so every TLS request and WSS upgrade must show the certificate that pairing pinned.
- `{"outcome": "no-response"}`: the server closed the connection without an HTTP response (RST or EOF; the cause is not compared). The TS server does this for every body over its route limit: 64 KiB by default, 400 KiB for diagrams, 3 MiB for pane images, 6 MiB + 1 KiB for file saves, 14 MiB for pane-chat attachments.

### WebSocket cases (`transport: "ws"`)

`request` has `path`, `listener` and `headers`. `steps` is a list of operations:

| op | Meaning |
|---|---|
| `send_text` | Send a text frame: `json` (serialized compactly) or `text`. |
| `send_binary` | Send a binary frame: `json` (compact UTF-8) or `base64`. |
| `recv` | Record the next data frame or the close (waits up to `timeout`, default 10 s). |
| `recv_until` | Skip frames until one matches, then record only that one. `where`: the frame's JSON object contains these key/value pairs. `contains`: text frames joined in arrival order contain this substring; the joined text is recorded (terminal output is split at different points on every run). A close, EOF or timeout also ends the wait and is recorded. |
| `expect_close` | Skip data frames until close, EOF or timeout, and record that. |
| `http` | Send an HTTP request (same fields as above) while the socket stays open. Record `{"kind":"http","status","body"}`. |
| `sleep` | Wait `seconds`. |
| `close` | The client closes with code 1000. |

Client frames are masked. Pings are answered with pongs and are not recorded.

`expect.handshake` is one of:
- `{"status": 101}`, plus `tls` for WSS;
- `{"status": 401|400, "raw": "HTTP/1.1 401 Unauthorized\r\n\r\n"}`: the exact bytes the server wrote before it destroyed the socket (no headers);
- `{"outcome": "no-response"}`: the socket was destroyed with no bytes written (an upgrade on a path that is not a WebSocket path).

`expect.frames` lists the recorded steps in order:
- `{"kind":"text","json":{…}}` when the text parses as a JSON object or array, otherwise `{"kind":"text","text":"…"}`;
- `{"kind":"binary","base64":"…"}`;
- `{"kind":"close","code":4001,"reason":"device-unpaired"}`;
- `{"kind":"eof"}` or `{"kind":"timeout"}`;
- `{"kind":"http",…}`.

### TLS certificate case (`transport: "tls-certificate"`)

The replayer opens a TLS connection to the TLS listener and records:
- the SHA-256 fingerprint, captured as `tls_fingerprint`;
- whether TLS 1.2 or newer was negotiated;
- from the certificate: subject CN (`KanVibe Desktop`), self-issued, RSA 2048, signature hash sha256, validity 7300 days (20 years).

The fingerprint value itself is not fixed, because every new data directory generates its own certificate. Two invariants are not replayed by these goldens: the certificate must be the byte-for-byte reuse of `<userData>/mobile-tls/{certificate,private-key}.pem`, and a restart must keep the fingerprint. A Rust test should check both separately.

## Variables, captures and oracles

Variables start with the fixture paths that `kvcontract/fixture.py` creates under a fresh fixture root:

| Variable | Value |
|---|---|
| `fixture_root` | the fixture root directory |
| `demo_scan_root` | `<root>/repos/demo-group` |
| `scratch_scan_root` | `<root>/repos/scratch-group` |
| `demo_repo` | `<root>/repos/demo-group/demo`: `main` holds `README.md` and `notes/todo.txt`; branch `existing-branch` has one extra commit |
| `scratch_repo` | `<root>/repos/scratch-group/scratch` |

Author and commit dates are fixed, so commit hashes are the same on every run. The server must reach these paths on the same filesystem.

`capture` selectors are dot paths into the observed result, for example `body.task.id` or `frames[1].json.surfaces`. `[n]` indexes an array. `[field=value]` picks the first array element whose `field` equals `value` as a string, for example `body.board.projects[name=demo].id`.

Oracles are actions the replayer performs that are not HTTP requests to the server.

| Oracle | Implemented by | Contract |
|---|---|---|
| `read_json_file {path}` | replayer (filesystem) | Reads a JSON file the server wrote. Used for `<worktree>/.kanvibe/targets.json`, which carries the task token `HMAC-SHA256(task_cli_secret, taskId)` and the hook client id. Waits up to 10 s for the file. |
| `write_file {path, content}` | replayer | Creates working-tree changes (diff routes) or dirty files (CLI delete 409). |
| `git {cwd, args}` | replayer | Runs git with user and system config disabled. Used for `git worktree add` before the register route. |
| `issue_pairing_code {}` → `{code, expiresAt}` | **server-specific** | Same as the desktop settings screen's `startMobilePairing()`: one live 6-digit code. |
| `issue_hook_install_ticket {}` → `{token, scriptSha256}` | **server-specific** | Same as `issueHookInstallScript(files)` with this fixed file list: `[{"filePath":"/tmp/kanvibe-contract-hook/status.sh","content":"echo kanvibe-contract\n","mode":493}]`. The golden install script body depends on this input. |

`replay.py` reaches the server-specific oracles in one of two ways:
- `--launch-rust`: the `kanvibe-server-qa oracle` subcommand over the QA runner's Unix socket.
- `--oracle-cmd CMD`: runs `CMD <name> '<json-args>'` and reads JSON from stdout, for a server that is already running.

## Comparison

`match(expected, actual)` is recursive:

- **Object**: the key sets must be equal (no missing keys, no extra keys). A key written as `{{var:x}}` is replaced with the variable's value before keys are compared; `diff-stats` uses task IDs as keys. Values are compared recursively.
- **Array**: same length, compared element by element in order.
- **Number, bool, null**: equal value and equal JSON type (`true` ≠ `1`). Integers and floats compare by value.
- **String**: if the whole string is one of the matchers below, the matcher decides. Otherwise every `{{var:x}}` inside it is replaced, and the result must equal the actual string exactly.

| Matcher (whole string) | Accepts |
|---|---|
| `{{any}}` | any value, including null |
| `{{any:string}}` / `{{any:nonempty}}` | string / non-empty string |
| `{{any:iso8601}}` | string `YYYY-MM-DDTHH:MM:SS[.fraction](Z\|±HH:MM)` |
| `{{any:uuid}}` | lowercase canonical UUID string |
| `{{any:hex64}}` / `{{any:hex}}` / `{{any:digits}}` / `{{any:base64}}` | strings of that alphabet |
| `{{any:int}}` / `{{any:number}}` / `{{any:bool}}` / `{{any:object}}` / `{{any:array}}` | that JSON type (bool is not a number) |
| `{{any:<kind>?}}` | the same, or null |
| `{{var:x}}` | exactly the variable's value (any JSON type) |
| `{{regex:R}}` | string that fully matches the Python regex `R` (dot matches newline) |
| `{{contains:S}}` | string that contains `S`; `{{var:x}}` inside `S` is replaced first |

## Volatile-field rules

The recorder turned each observed response into `expect` with these rules, applied in this order. Every replayer compares only what the rules leave behind, so the comparison is deterministic.

1. **Per-case overrides** (`volatile` in the removed `scenario.py`, keyed by JSON path with `[*]` for any index) replaced the value with the matcher given. They are used for:
   - tmux tab names: `{{regex:tmux|bash}}`. tmux renames a new window from `tmux` to `bash` shortly after creation, and the `logs` name appears after the rename case;
   - terminal screen and stream text: `{{any:string}}` or `{{contains:…}}`;
   - diagram image bytes and size;
   - the background-sync status at start time;
   - the AI-login PTY error text;
   - the JS engine's JSON parse message in the hook-status 500.
2. **Object keys** equal to a variable value become `{{var:name}}`.
3. **Strings equal to a variable value** of 8 or more characters become `{{var:name}}`. If no whole value matches, every substring equal to such a value is replaced, longest value first; for example a worktree path becomes `{{var:demo_repo}}__worktrees/feat-a`. A value captured by the same case is not substituted into that case's own response; the type rule below applies to it instead.
4. **Type rules** for the remaining strings: ISO-8601 timestamp → `{{any:iso8601}}`, UUID → `{{any:uuid}}`, 64 lowercase hex characters (tokens, account handles, fingerprints) → `{{any:hex64}}`.
5. **Integer timestamps**: an integer of at least 10^12 (epoch milliseconds) under a key ending in `At`, `Ms`, `_at`, `Time` or `time` becomes `{{any:int}}`.

Everything else is compared exactly. That includes every Korean `error` string, every `reason` and `code` enum, field presence, `null` values and array order. The order of keys inside a JSON object is not compared. Array order is stable because creation steps are spaced by at least one second.

## Environment the goldens assume

The recorder created this environment, and `replay.py --launch-rust` creates the same one. Any other harness must create an equivalent one, or the replies change. Examples: `defaultSessionType`, the session dependency 409, the AI account list and the login output.

- **Fresh state**: an empty `KANVIBE_APP_DATA_DIR` (database and `mobile-tls/`), `KANVIBE_QA_MODE=1`, a fixed hook port. The TLS listener is on port + 10, and the plaintext listener binds 127.0.0.1.
- **Narrow child environment**: the parent environment is not inherited. Only `LANG`, `LC_ALL`, `USER` and `LOGNAME` are copied. The rest is set explicitly:
  - `PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin`. `git`, `tmux` and `gh` resolve from the system. `claude`, `codex`, `gemini`, `opencode`, `herdr` and `zellij` must be absent.
  - `HOME`, `XDG_*`, `XDG_RUNTIME_DIR` and `TMUX_TMPDIR` all point inside the run directory, so the user's tmux server, shell config, CLI accounts and `gh` login are never touched. `TMUX_TMPDIR` and `XDG_RUNTIME_DIR` use a short temp path because of the 108-byte Unix socket limit. A `~/.bash_profile` sets `PS1='$ '`.
  - `SHELL=/bin/bash`, `TERM=xterm-256color`, `CI=1`.
- **Devices**: a fresh install has no paired devices. Pairing codes come only from the `issue_pairing_code` oracle. The dev route `/api/mobile/dev/pairing-code` is recorded as disabled (401 without a token, 404 with one), which is how packaged and QA builds behave.

## Behaviors the goldens pin that are easy to miss

- Feature routes are dispatched before the main mobile routes. As a result:
  - `tasks/search` and `tasks/done` are reserved task IDs;
  - `POST /tasks/:id/notifications/read` returns `updatedCount`, not `count`.
- Hook and CLI paths match the exact `request.url`. A query string, or another method, gets 404 `Not found`.
- Hook status errors carry a numeric `status` field in the body. Invalid JSON gives 500 with the parse message. The status value is lowercased (`REVIEW` → `review`). Mobile `PATCH …/status` is case-sensitive.
- An `Origin` header gives 403 on every HTTP request, including TLS and before auth. WebSocket upgrades do not check `Origin`.
- `POST …/panes/:paneId/connection` always sets `Cache-Control: no-store`. On plaintext it answers `connection:null`.
- Close codes:
  - 4000 with a surface reason (`no-session`, …);
  - 4001 `device-unpaired`, after the device deletes itself;
  - 4002 `session-changed`, when the task's session type changes;
  - 1008 `invalid-login-request`;
  - 1011 `login-open-failed`;
  - 1000 `login-finished`.
- Event socket commands answer only the sender. Text frames that are not JSON, binary frames, and frames over 1 KiB get no reply.

## Known TS race (worked around, not pinned)

After a stream `resize`, the TS app re-attaches the pane mirror and sends a second snapshot about 100 ms later. Keystroke echo produced in that window can be missing from the stream, even though the pane received the input. `ws.stream.mirror` waits 2 s after the first snapshot before typing. The Rust server should not reproduce the drop.
