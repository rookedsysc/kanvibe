Paseo는 데몬이 관리하는 에이전트와 대화한다. KanVibe의 Pane Chat은 이미 열린 터미널 pane에 연결한다.

  • Paseo는 agentId로 프롬프트를 보낸다. 데몬이 에이전트 이벤트를 타임라인으로 전달한다.

  • KanVibe의 대화 기록 화면은 별도 조회 화면이다. 현재 GPUI 작업 브랜치에서 연결된 화면도 이 대화 기록 화면이다.

  4. Pane Chat 서비스가 공급자 기록을 다시 읽는다. 채팅 UI가 변경된 메시지를 표시한다. KanVibe의 답변 표시

상세 설명

Paseo는 무엇을 기준으로 전송하는가 흐름도로

Paseo의 전송 대상은 데몬이 관리하는 에이전트다. 에이전트 ID는 그 실행 대상을 지정한다. 채팅 앱의 dispatchComposerAgentMessage는 메시지 ID를 만든다. 앱은 사용자 메시지를 먼저 표시하고 send_agent_message_request를 보낸다. 데몬은 agentId를 해석하고 sendPromptToAgent로 공급자에 프롬프트를 넘긴다. 예를 들어 Claude 연결은 Claude Agent SDK를 사용한다. 앱은 데몬의 수락 또는 거절 응답을 받아 사용자 메시지의 전송 상태를 정리한다. 수락 응답과 답변 완료는 시점이 다르다.

Paseo의 답변은 언제 화면에 나타나는가 흐름도로

Paseo는 공급자 이벤트를 받는 동안 답변을 갱신한다. 데몬은 이벤트에 순번을 붙이고 agent_stream으로 보낸다. 타임라인은 연속으로 들어오는 답변 조각을 하나의 답변 행에 합친다. 같은 도구 호출의 시작과 완료도 한 항목의 상태로 합친다. 채팅 앱은 저장된 기록과 진행 중인 최신 항목을 한 화면에 배치한다. 사용자 입력, AI 답변, 추론, 도구 실행은 각각에 맞는 행으로 표시한다.

Paseo는 연결이 끊겨도 어떻게 이어서 읽는가 흐름도로

Paseo 앱은 마지막으로 받은 타임라인 위치를 데몬과 대조한다. 위치에는 타임라인 세대를 나타내는 epoch와 순번 seq가 들어간다. 데몬이 이미 최신이라고 응답하면 앱은 저장된 내용을 계속 표시한다. 누락된 항목이 있으면 앱은 fetch_agent_timeline_request로 이후 항목을 조회한다. 더 최신인 페이지가 남아 있으면 다음 페이지도 가져온다. 이전 대화는 같은 화면에서 과거 방향으로 읽을 수 있다. 데몬이 에이전트를 재개할 때는 공급자가 보존한 기록으로 타임라인을 다시 만든다.

KanVibe는 어떤 대화가 pane에 열려 있는지 어떻게 아는가 흐름도로

Pane Chat은 터미널 pane의 현재 실행 프로세스를 조사하고 그 프로세스가 연 대화 기록을 찾는다. Claude Code에서는 프로세스의 세션 정보나 이미 확인한 연결이 근거가 될 수 있다. Codex에서는 화면에 표시된 스레드 ID로 그 스레드의 기록을 찾는 경로도 있다. 같은 작업 폴더에 여러 기록이 있더라도 기록의 최신 시각만으로 전송 대상을 고르지 않는다.

정확한 기록을 연결할 수 있으면 서비스가 대상 토큰인 targetToken을 발급한다. 서비스는 전송 직전에 pane, 프로세스, 대화의 일치 여부를 확인한다. 연결에 실패하면 전송을 비활성화한다. 읽을 수 있는 CLI 화면이 있으면 화면 내용을 대신 표시할 수 있다.

KanVibe는 항상 터미널에 타이핑하는가 흐름도로

KanVibe에는 터미널 입력과 Codex 스레드 API의 두 전송 경로가 있다.

  • 터미널 입력 경로는 준비된 입력란에 프롬프트를 붙여넣고 Enter를 따로 보낸다. Claude Code에서는 Enter 직전에 해당 입력란에 붙여넣은 내용이 남아 있는지 확인한다.
  • Codex 화면 연동이 활성화되어 있고 대화가 확인되면 일반 프롬프트를 해당 스레드의 Codex app-server API로 보낸다. 내장 슬래시 명령은 터미널 입력 경로를 쓴다.

pane에서 다른 대화로 이동하면 이전에 받은 targetToken으로 보낸 요청은 대상 변경으로 거절될 수 있다. 쓰기 시도 뒤 결과가 불명확한 경우도 서비스가 별도로 다룬다. 그래서 전송 오류가 표시됐다는 사실만으로 CLI에 입력이 도달했는지 판단할 수 없다.

KanVibe는 무엇을 읽어 말풍선을 만드는가 흐름도로

Pane Chat은 공급자 기록에서 프롬프트와 답변을 읽는다. 터미널 화면은 선택창이나 입력란처럼 현재 CLI 상태를 판별하는 데 쓴다. 예를 들어 Claude의 질문 선택창이 뜨면 Pane Chat은 화면을 해석해 선택지를 보여 줄 수 있다.

Electron 서비스는 구독 중에 기록을 주기적으로 다시 읽는다. 로컬 기록 파일을 감시할 수 있으면 변경 알림도 이용한다. 모바일은 호스트에서 받은 pane-chat-rows를 적용한다. 순서가 어긋나면 모바일 컨트롤러가 스냅샷을 다시 요청한다. 따라서 KanVibe의 화면도 실행 중에 갱신된다. 답변의 표시 시점은 공급자가 읽을 수 있는 기록을 남기는 시점에도 영향을 받는다.

현재 KanVibe GPUI에서 어떤 화면이 열리는가

현재 perf/rust-gpui 작업 브랜치에서 대화 기록을 열면 InlineAiChatView가 첫 기록 목록을 조회한다. 왼쪽에서 공급자나 검색어로 세션을 찾고, 오른쪽에서 선택한 세션의 메시지를 읽는다. 터미널로 돌아가면 GPUI는 해당 기록 뷰를 버린다.

같은 브랜치의 GPUI 터미널에는 Pane Chat 전환 버튼을 그리는 코드가 있다. 이 버튼에는 채팅 화면을 여는 클릭 핸들러가 연결되어 있지 않다. Rust 호스트에는 Pane Chat 서비스를 호출하는 경로가 있다. 위의 실시간 Pane Chat 화면 설명은 Electron과 Flutter 모바일의 실제 진입점, 그리고 해당 호스트 서비스 코드에 근거한다.
