# KanVibe Mobile: keep your task moving from your phone

KanVibe Mobile is the iOS and Android companion to KanVibe Desktop. Check progress, open the same task terminal, send input, and switch between saved PCs. Your repositories and processes stay on the connected PC.

  <p><strong>Interface language:</strong> Mobile currently uses Korean interface labels. This guide gives English names with the Korean labels in parentheses.</p>

## Build Mobile and prepare Desktop

Mobile is currently available from source. Use an iOS or Android development environment and [FVM](https://fvm.app/) to install the Flutter version pinned in `mobile/.fvmrc`. In a checkout of the [KanVibe repository](https://github.com/rookedsysc/kanvibe), run:

```bash
cd mobile
fvm install
fvm flutter pub get
fvm flutter run
```

Select your connected phone or simulator when prompted. iOS builds need macOS and the Xcode version required by the current mobile dependencies. See the [Mobile developer README (Korean)](https://github.com/rookedsysc/kanvibe/blob/main/mobile/README.md) for the current toolchain, release signing, and push configuration.

[Install Desktop](/en/installation) and keep it running on the PC you want to use. The Desktop build must include Mobile support; terminal tab creation, resizing, and the notification inbox also need a Desktop build that supports those features.

The phone must be able to reach the saved PC address and port. Use the same reachable local network, or a private network such as Tailscale when away from home. Receiving an internet push notification does not make the PC's terminal reachable automatically.

## Pair your phone once

1. In Desktop, open **Settings → Mobile Connection → Create pairing code**.
2. In Mobile, enter the **Desktop address** (<span lang="ko" translate="no">데스크탑 주소</span>), **Port** (<span lang="ko" translate="no">포트</span>), and the six-digit **pairing code** (<span lang="ko" translate="no">연결 코드</span>). Use port **9736** for a packaged Desktop app or **19736** for a development build. **PC name** (<span lang="ko" translate="no">PC 이름</span>) is optional.
3. Tap **Connect** (<span lang="ko" translate="no">연결</span>). The board opens, and Mobile stores the connection in the device's secure storage for future use.

The code expires after **five minutes** and can be used once. Create a new code if it expires or has already been used. Enter the PC's network address rather than `localhost` when connecting from a physical phone. Find it in macOS **System Settings → Network**, or run `ipconfig getifaddr en0` on the PC.

## Find the task that needs you

On a phone, tasks appear as vertical sections grouped by status. On a tablet, they appear in Kanban columns. Both show the same Desktop tasks and project colors.

- Open the **project filter** (<span lang="ko" translate="no">프로젝트 필터</span>) to search and select one or more projects. Selecting a root project includes its linked worktree tasks on the same host.
- Tap a task to open its details and terminal. Change its status from the task's status control.
- Use **New task** (<span lang="ko" translate="no">새 태스크</span>) to choose a project and base branch and create follow-up work. You can also start from the open task's header.
- Moving a task to **DONE** keeps its branch, worktree, and terminal session. Deleting a task is the separate resource-cleanup action.

## Use the same running terminal

Each terminal tab displays one pane. Choose a tab to read its output, then tap the terminal to bring up the keyboard and send input to the actual session. Use the **+** at the right of the tab bar to add a shell tab to the current task.

Swipe to read earlier output. In full-screen programs that accept mouse input, vertical swipes become wheel events (except Herdr, where swipes always scroll the view). With supported tmux and plain-terminal sessions, the terminal resizes to fit the phone, rotation, and keyboard. While Mobile is attached, this also changes the size of that terminal on the PC; leaving the tab or putting Mobile in the background restores the applicable PC size. Herdr, Zellij, and older Desktop builds keep their source grid and allow scrolling in both directions.

For unattended work, use a persistent session such as Herdr, tmux, or zellij. A plain `terminal` shell belongs to Desktop and does not survive the Desktop app quitting.

## Switch between your PCs

Tap the current PC name at the top of the board to open **Connected PCs** (<span lang="ko" translate="no">연결된 PC</span>), then choose **Add PC** (<span lang="ko" translate="no">PC 추가</span>) to pair another computer. Give each PC a recognizable name. Tap a saved PC to open its board without entering a new code.

Mobile keeps the project filter separately for each PC during the app session. If one PC is offline, return to the PC list and choose another. Each selected board belongs to that PC; switching PCs does not combine their task lists.

Delete a PC from **Connected PCs** (<span lang="ko" translate="no">연결된 PC</span>) to remove its saved connection and revoke this device on that PC. Other PC connections remain. If the PC cannot be reached, also remove this device in that PC's Desktop settings later. After deleting the current PC, choose another PC yourself.

## Read the notification inbox

The board's **Notifications** (<span lang="ko" translate="no">알림</span>) button opens the selected PC's Desktop inbox. The badge counts unread notifications. Filter **All / Unread** (<span lang="ko" translate="no">전체 / 안 읽음</span>), mark individual notifications read (<span lang="ko" translate="no">읽음 처리</span>), or mark all read (<span lang="ko" translate="no">모두 읽음</span>). Desktop and Mobile share this read state and the most recent 100 notifications.

Tap a task notification to mark it read and open the latest task. If the task was deleted, Mobile shows an explanation. Notifications without a task can be read in the inbox; any associated Desktop-only action still needs Desktop.

## Understand foreground updates and background push

While Mobile is active, it connects to saved PCs over authenticated WebSockets. Hook events update task status and can show system notifications. An event from another saved PC can take you to that PC and its task when tapped.

When Mobile is in the background or the screen is locked, event and terminal sockets close. Background notifications require **both mobile Firebase/APNs configuration and a Desktop push relay**, plus OS notification permission. Source builds without that configuration still support the app and foreground WebSocket updates. Follow the [push setup instructions (Korean)](https://github.com/rookedsysc/kanvibe/blob/main/mobile/README.md#백그라운드-알림-설정) if you need background delivery.

The PC must remain running to send new hook events. After tapping a push, task loading and terminal input still connect directly to its saved address. Android force-stop prevents push delivery until you reopen the app. Background execution and notification delivery depend on the OS; this is not a continuously running background terminal.

## If the connection does not work

| Symptom | What to check |
| --- | --- |
| "Code is incorrect or expired" (<span lang="ko" translate="no">코드가 맞지 않거나 만료되었습니다</span>) | Check for typos, then create a fresh code; it expires in five minutes and is single-use. |
| "Already registered PC" (<span lang="ko" translate="no">이미 등록된 PC입니다</span>) | Choose that PC from **Connected PCs** (<span lang="ko" translate="no">연결된 PC</span>) instead of pairing again. |
| PC cannot be reached | Desktop is running, the address and port are correct, and local network or Tailscale routing and firewall rules allow access. |
| Notification arrives but task does not open | The saved PC address must also be reachable from the phone's current network. |
| "No terminal session" (<span lang="ko" translate="no">이 태스크에는 터미널 세션이 없습니다</span>) or terminal unavailable | Use a Mobile-compatible Desktop build. If Mobile says Herdr is not installed, connect a Herdr session on Desktop to install it. Tasks without a project or branch cannot restore a missing session automatically. |
| No background notifications | Check mobile Firebase/APNs configuration, Desktop relay configuration, OS permission, and whether Android has force-stopped the app. |
| Task from a notification is missing | The task may have been deleted or its PC connection removed. Open the board or PC list to choose current work. |
