# Features

KanVibe connects the Kanban board, terminal sessions, git worktrees, and AI agent hooks into one workflow.

## Real-time Kanban board

  <img src="/screenshots/board.png" alt="KanVibe main Kanban board" />
  <figcaption>Manage TODO, PROGRESS, PENDING, REVIEW, and DONE with project colors and task metadata.</figcaption>
</figure>

<div className="kv-status-flow">
  <span>TODO</span><span>PROGRESS</span><span>PENDING</span><span>REVIEW</span><span>DONE</span>

- Move cards between columns with drag and drop, and set card order with the sort filter.
- Read project color, priority, PR, and session labels directly from each card.
- Paginate the DONE column for long-running projects.

## Task detail workspace

<figure className="kv-shot">
  <img src="/screenshots/task-detail.png" alt="Per-task terminal workspace" />
  <figcaption>Each task provides an isolated terminal interface so agent runs, direct commands, builds, and tests stay freely interchangeable.</figcaption>
</figure>

- Pick the session backend per task: tmux, zellij, or a plain terminal that KanVibe runs without a multiplexer.
- Every task owns its terminal, so you can continue an AI-run task with direct shell commands whenever needed.
- Switch info, hook status, AI chat, and PR actions through numbered dock shortcuts.
- Moving a task to DONE keeps its branch, worktree, and terminal session in place. Cleanup runs only when you delete the task.

## Terminal tabs

Open several terminals inside one task to keep a server, a test run, and an agent session apart.

<figure className="kv-shot">
  <img src="/screenshots/terminal-tabs.png" alt="Task detail screen with three terminal tabs open: claude, dev server, and test" />
  <figcaption>Add a tab with the <code>+</code> button at the right end of the tab bar above the terminal. The first five tabs also show the shortcut that jumps straight to them, and the selected tab's terminal fills the area below.</figcaption>
</figure>

- Add, switch, and close tabs from the tab bar, rename with a double-click, and reorder by dragging.
- While the task info panel is open it overlays the left portion of the tab bar. Click the terminal outside the panel, or press the task info dock button again, to reveal the whole bar.
- Tabs on tmux and zellij sessions stay **synchronized in both directions** with tmux windows and zellij tabs. A window created outside KanVibe with `tmux new-window` shows up in the tab bar, and clicking a tab moves the multiplexer's active target too.
- Because KanVibe draws its own tab bar, the tmux status bar and the zellij tab bar are turned off — only for sessions KanVibe creates. tmux is turned off on every reattach, so sessions made before the tab bar shipped get cleaned up too. zellij fixes its layout when the session is created, so it only applies to sessions created after that.
- On `terminal` sessions KanVibe runs one shell per tab. Each tab keeps its own scrollback across switches, and the shells stay alive while the app is running.

Key combinations are listed in the terminal tabs section of the [shortcuts](/en/shortcuts) page.

    <figcaption>Search matches conversation body text as well as session titles, then opens the relevant message context.</figcaption>

- Load Claude, Gemini, Codex, and OpenCode history on demand inside the task detail AI chat panel.
- Provider filters can be selected together; selected providers are combined with OR before other filters narrow the results.
- Chat search narrows both the session list and message detail, while role chips refine user, assistant, system, developer, reasoning, tool, and other messages.
- Message bubbles include provider badges so mixed-agent context stays readable.

## AI usage

<figure className="kv-shot">
  <img src="/screenshots/ai-usage.png" alt="Task detail screen with remaining Claude, Codex, and Gemini usage open" />
  <figcaption>Check remaining subscription usage in one place from the bottom dock icon or <code>Cmd/Ctrl+0</code>.</figcaption>
</figure>

- Reads the sign-in each CLI already stored locally, so there is no separate API key to enter.
- Normalizes the different window shapes per provider (5-hour, 7-day, per-model) into the same bar, with reset times and plan tier.
- Bar colors shift to warning and danger as a limit gets close.
- When several accounts are registered, each one is queried separately and labeled so you can tell them apart.
- Opening the panel shows the last result first and reports refreshing above it, so it never opens blank after a restart.

## Project filters, directory scan, and notifications

<div className="kv-grid">
  <figure className="kv-shot">
    <img src="/screenshots/project-filter.png" alt="Project filter" />
    <figcaption>Toggle visible projects from the keyboard.</figcaption>
  </figure>
  <figure className="kv-shot">
    <img src="/screenshots/notifications.png" alt="Notification center" />
    <figcaption>Click a notification to jump directly to the linked task workspace.</figcaption>
  </figure>
</div>

- Project filters narrow the board to the repositories you want to focus on.
- The magnifying-glass button between the project filter and + New Task opens the project registry dialog for directory scanning and repository registration.
- The notification center and system notifications collect AI agent status changes, PR events, and background sync events.
- Notifications linked to a task open that task detail view immediately when clicked.
- In the notification list, `Space` only marks the selected notification as read, while `Enter` opens its target.
- Entering a task detail view automatically marks every notification for that task as read.
- Kanban cards show an unread notification count badge so you can spot pending updates straight from the board.

## AI agent hooks

| Agent | Automatic status flow | Install location |
| --- | --- | --- |
| Claude Code | user prompt → PROGRESS, question → PENDING, response done → REVIEW | `.claude/hooks/`, `.claude/settings.json` |
| Gemini CLI | BeforeAgent → PROGRESS, AfterAgent → REVIEW | `.gemini/hooks/`, `.gemini/settings.json` |
| Codex CLI | UserPromptSubmit → PROGRESS, PermissionRequest → PENDING, Stop → REVIEW | `.codex/hooks.json`, `.codex/config.toml` |
| OpenCode | message.updated → PROGRESS, question.asked → PENDING, session.idle → REVIEW | `.opencode/plugins/` |
