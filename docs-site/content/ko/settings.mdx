# 설정

KanVibe 설정 페이지는 화면 표시, 터미널 pane 구성, 알림, 작업 생성 기본값, 백그라운드 Sync를 한곳에서 관리합니다. 설정은 앱 내부 SQLite 데이터베이스에 저장되며, 일부 항목은 저장 즉시 보드와 태스크 상세 화면에 반영됩니다.

## 외관

| 항목 | 선택지 | 동작 |
| --- | --- | --- |
| 테마 | 시스템, 다크, 라이트 | 앱 전체의 색상 모드를 바꿉니다. 시스템은 macOS 표시 모드를 따르고, 다크/라이트는 사용자가 고정한 값으로 즉시 적용됩니다. |

테마 변경은 설정을 저장한 뒤 바로 화면에 반영됩니다. 여러 창이나 보드에서 같은 설정을 읽기 때문에 다음 실행 때도 동일한 모드로 시작합니다.

## Pane 레이아웃

설정 페이지의 **Pane 레이아웃 설정** 링크는 tmux 세션이 열릴 때 사용할 pane 분할과 각 pane의 시작 명령을 관리하는 화면으로 이동합니다.

| 항목 | 설명 |
| --- | --- |
| 글로벌 기본값 | 프로젝트별 설정이 없을 때 모든 새 터미널 세션에 적용되는 기본 레이아웃입니다. |
| 프로젝트별 설정 | 특정 프로젝트만 다른 pane 구성과 명령을 쓰도록 override합니다. override가 없는 프로젝트는 글로벌 기본값을 사용합니다. |
| 레이아웃 타입 | `1분할`, `상하 2분할`, `좌우 2분할`, `좌 + 우상하`, `좌상하 + 우`, `4분할` 중에서 선택합니다. |
| Pane 시작 명령어 | 각 pane 위치에 실행할 명령을 입력합니다. 예를 들어 한 pane은 `pnpm dev`, 다른 pane은 테스트나 로그 확인 명령으로 시작할 수 있습니다. |
| 저장 / 초기화 | 저장하면 이후 생성되는 세션에 반영됩니다. 프로젝트별 설정은 **글로벌 기본값으로 초기화**해 override를 제거할 수 있습니다. |

Pane 레이아웃은 태스크별 터미널 자유도를 높이는 핵심 설정입니다. 반복적으로 여는 서버, 테스트, 로그 tail 명령을 pane마다 지정해두면 새 worktree를 열 때마다 동일한 작업 공간을 만들 수 있습니다.

## 상세 페이지

| 항목 | 기본값 | 동작 |
| --- | --- | --- |
| 사이드바 기본 접기 | 꺼짐 | 태스크 상세 페이지에 들어갈 때 왼쪽 정보 패널을 접은 상태로 시작할지 정합니다. 터미널을 넓게 보고 싶으면 켜고, 제목/프로젝트/우선순위/세션 정보를 항상 보고 싶으면 끕니다. |

이 설정은 태스크 상세 워크스페이스 진입 방식만 바꾸며, 태스크 데이터나 터미널 세션에는 영향을 주지 않습니다.

## 작업 생성

| 항목 | 선택지 | 동작 |
| --- | --- | --- |
| 기본 세션 타입 | `tmux`, `zellij`, `terminal` | 새 태스크를 만들 때 기본으로 선택되는 터미널 세션 백엔드를 정합니다. tmux는 기본값이며, zellij를 쓰려면 로컬 또는 원격 대상 환경에 zellij가 설치되어 있어야 합니다. `terminal`은 멀티플렉서 없이 KanVibe가 셸을 직접 띄우는 방식이라 별도 설치가 필요 없지만, 앱을 끄거나 원격 연결이 끊기면 실행 중이던 작업도 함께 사라집니다. |

세션 타입은 새로 생성하는 태스크의 기본 선택값입니다. 기존 태스크의 세션 타입을 일괄 변경하지는 않습니다.

## 알림

| 항목 | 선택지 | 동작 |
| --- | --- | --- |
| 시스템 알림 | 켜기 / 끄기 | 작업 상태 변경, PR 이벤트, 백그라운드 Sync 검토 항목을 시스템 알림으로 받을지 정합니다. |
| 알림 받을 상태 | PROGRESS, PENDING, REVIEW | 선택한 상태로 태스크가 변경될 때만 알림을 보냅니다. 기본값은 PROGRESS, PENDING, REVIEW입니다. TODO와 DONE은 사용자가 직접 관리하는 경우가 많아 상태 필터에 포함하지 않습니다. |

알림 센터와 시스템 알림은 AI 에이전트 상태 변경, PR/백그라운드 Sync 이벤트를 알려줍니다. 태스크와 연결된 알림을 클릭하면 해당 태스크 상세 워크스페이스로 바로 이동합니다. 상태 필터를 줄이면 PENDING 질문이나 REVIEW 완료처럼 바로 확인해야 하는 이벤트만 남길 수 있습니다.

## 키보드

| 항목 | 기본값 | 동작 |
| --- | --- | --- |
| Vim 스타일 보드 조작 | 켜짐 | 보드에서 `h`/`j`/`k`/`l` 포커스 이동, `n` 새 작업, `dd` 삭제, `:move` 상태 변경을 쓸 수 있게 합니다. 꺼도 방향키 이동은 유지됩니다. |

자세한 키 목록은 [단축키](/ko/shortcuts) 문서를 참고하세요.

## 백그라운드 Sync

| 항목 | 범위 | 동작 |
| --- | --- | --- |
| 백그라운드 Sync | 켜기 / 끄기 | 앱이 열려 있는 동안 프로젝트 worktree, PR 상태, task pull 결과를 주기적으로 확인합니다. |
| Sync 주기 | 1~1440분 | 백그라운드 Sync를 실행하는 간격입니다. 기본값은 10분이며, 값은 분 단위로 저장됩니다. 잘못된 값은 저장하지 않고 이전 유효 값을 유지합니다. |

백그라운드 Sync는 merge 완료 PR, 새로 발견된 worktree, pull 성공/실패, PR 조회 실패 같은 검토 항목을 알림으로 모읍니다. Sync 단계 중 하나가 실패해도 나머지 단계는 계속 실행되며, 실패 이유는 백그라운드 Sync 검토 알림에 표시됩니다.
