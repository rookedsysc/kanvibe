# 功能

KanVibe 将看板、终端会话、git worktree 与 AI 代理 hooks 连接成一个工作流。

## 实时看板

<figure className="kv-shot">
  <img src="/screenshots/board.png" alt="KanVibe 主看板" />
  <figcaption>用项目颜色和任务元数据管理 TODO、PROGRESS、PENDING、REVIEW、DONE。</figcaption>
</figure>

<div className="kv-status-flow">
  <span>TODO</span><span>PROGRESS</span><span>PENDING</span><span>REVIEW</span><span>DONE</span>
</div>

- 通过拖拽在列之间移动卡片，并用排序筛选器决定卡片顺序。
- 在卡片上直接查看项目颜色、优先级、PR 与会话标签。
- DONE 列支持分页，适合长期项目。

## 任务详情工作区

<figure className="kv-shot">
  <img src="/screenshots/task-detail.png" alt="每个任务的终端工作区" />
  <figcaption>每个任务都提供独立终端界面，可在 AI 代理执行、直接命令、构建和测试之间自由切换。</figcaption>
</figure>

- 可为每个任务选择会话后端：tmux、zellij，或由 KanVibe 直接启动 shell、不使用多路复用器的 terminal。
- 每个任务都有自己的终端，因此可把 AI 代理执行的任务随时接回并用 shell 命令继续处理。
- 用编号 dock 快捷键切换信息、hook 状态、AI 聊天和 PR 操作。
- 将任务移动到 DONE 时，branch、worktree 和终端会话会被保留。只有删除任务时才会清理资源。

## 终端标签页

可在同一个任务中打开多个终端，把服务器、测试和代理执行分开。

<figure className="kv-shot">
  <img src="/screenshots/terminal-tabs.png" alt="打开了 claude、dev server、test 三个终端标签页的任务详情界面" />
  <figcaption>用终端上方标签栏右端的 <code>+</code> 按钮新增标签页。前五个标签页还会显示直接跳转的快捷键，所选标签页的终端就在下方展开。</figcaption>
</figure>

- 在标签栏中新增、切换、关闭标签页，双击重命名，拖拽调整顺序。
- 任务信息面板打开时会遮住标签栏左侧的一部分。点击面板外的终端，或再次按 dock 的任务信息按钮将其关闭，即可显示完整标签栏。
- tmux 和 zellij 会话的标签页与 tmux window、zellij tab **双向同步**。在 KanVibe 之外用 `tmux new-window` 创建的 window 也会出现在标签栏中；点击标签页时，多路复用器的活动对象也会随之切换。
- 由于 KanVibe 自己绘制标签栏，tmux 状态栏和 zellij 标签栏会被关闭 —— 仅限 KanVibe 创建的会话。tmux 在每次重新连接时都会关闭，因此标签栏上线前创建的会话也会被整理；zellij 的布局在创建会话时就已确定，所以仅对之后新建的会话生效。
- 在 `terminal` 会话中，KanVibe 会为每个标签页单独启动 shell。切换标签页时各自的 scrollback 会保留，且只要应用在运行，shell 就会一直存在。

按键组合请参见[快捷键](/zh/shortcuts)文档的终端标签页一节。

    <figcaption>在左侧 provider 图标栏中同时选择多个代理时，会以 OR 条件显示所有匹配会话。</figcaption>
  </figure>
  <figure className="kv-shot">

- 在任务详情的 AI 聊天面板中按需加载 Claude、Gemini、Codex、OpenCode 历史。
- Provider 过滤器可同时选择多个图标，已选择的 provider 会先以 OR 条件合并，再由其他过滤器继续缩小范围。
- 聊天搜索会同时缩小会话列表和消息详情，role chip 可进一步过滤用户输入、AI 回复、系统输入、开发者输入、推理、工具和其他消息。
- 每个消息气泡都会显示 provider 徽章，便于区分多代理上下文。

## 运行中的 AI 会话与子任务

<div className="kv-grid">
  <figure className="kv-shot">
    <img src="/screenshots/live-sessions-board.png" alt="看板卡片在 tmux 徽章旁显示运行中的代理图标" />
    <figcaption>tmux 徽章旁会按代理显示图标和数量，可直接在看板上看出哪个任务在运行哪些代理、各有几个。</figcaption>
  </figure>
  <figure className="kv-shot">
    <img src="/screenshots/live-sessions-panel.png" alt="任务详情面板显示运行中的 claude 会话及两个子任务" />
    <figcaption>会话面板会显示每个会话当前正在处理的工作，以及正在执行的子任务。</figcaption>
  </figure>
</div>

- 将焦点或鼠标停留在看板卡片上片刻即可打开会话面板；快速掠过卡片时不会打开。
- 每个会话行会显示该会话当前正在做的事，取自最近一次 AI 回复，因此在长对话中也能指向当前任务。
- 运行中的会话会带有移动的进度条。由于无法得知剩余工作量，它以动态而非比例传达进度；在要求减少动效的环境下会静止显示。
- 子任务以挂在会话下的分支绘制，可以看出归属哪个会话以及列表在哪里结束。
- 在任务详情中，dock 的运行中会话项会打开同一个面板：没有 PR 时为 `Mod+4`，有 PR 时为 `Mod+5`。
- 点击会话会切换到该会话所在的 tmux window，并把输入焦点移到终端。
- 运行判定叠加两个依据：代理挂在 tmux pane 上时，即使在等待输入也算运行中；即使看不到 pane，只要会话记录刚刚更新也算运行中。
- 只有面板打开时才读取会话记录。看板徽章只需一次 tmux 查询，卡片再多也不会增加开销。

子任务统计依赖各代理记录的内容，因此支持范围不同。

| 代理 | 子任务统计 |
| --- | --- |
| Claude Code | 支持 |
| Codex | 支持 |
| OpenCode | 视版本而定 |
| Gemini CLI | 不支持 |

不使用 tmux 的 zellij 和 terminal 会话仅依据记录活动判定，因此等待输入的会话可能显示为空闲。

## 项目过滤、目录扫描与通知

<div className="kv-grid">
  <figure className="kv-shot">
    <img src="/screenshots/project-filter.png" alt="项目过滤" />
    <figcaption>通过键盘切换看板中可见的项目。</figcaption>
  </figure>
  <figure className="kv-shot">
    <img src="/screenshots/notifications.png" alt="通知中心" />
    <figcaption>点击通知即可直接进入关联任务的详情工作区。</figcaption>
  </figure>
</div>

- 项目过滤可快速缩小看板范围，只保留当前要关注的仓库。
- 位于项目筛选和 + 新任务之间的放大镜按钮会打开用于目录扫描和仓库注册的项目注册对话框。
- 通知中心和系统通知会集中展示 AI 代理状态变化、PR 事件和后台 Sync 事件。
- 已关联任务的通知被点击后，会立即打开对应任务详情页。
- 在通知列表中，`Space` 只将所选通知标记为已读，`Enter` 才会打开目标页面。
- 进入任务详情页后，该任务的通知会自动全部标记为已读。
- 看板卡片会以徽章显示未读通知数量，可直接在看板上确认。

## AI 代理 Hooks

| Agent | 自动状态流 | 安装位置 |
| --- | --- | --- |
| Claude Code | 用户提示 → PROGRESS，提问 → PENDING，回复完成 → REVIEW | `.claude/hooks/`, `.claude/settings.json` |
| Gemini CLI | BeforeAgent → PROGRESS，AfterAgent → REVIEW | `.gemini/hooks/`, `.gemini/settings.json` |
| Codex CLI | UserPromptSubmit → PROGRESS，PermissionRequest → PENDING，Stop → REVIEW | `.codex/hooks.json`, `.codex/config.toml` |
| OpenCode | message.updated → PROGRESS，question.asked → PENDING，session.idle → REVIEW | `.opencode/plugins/` |
